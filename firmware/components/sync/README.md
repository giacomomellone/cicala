# sync

Manifest check, per-language bundle download, sha256 + ed25519 verification,
and an atomic swap in LittleFS. The full flow is specified in
[docs/sync_protocol.md](../../../docs/sync_protocol.md); any failure keeps the
old bundle.

Three things in this contract were written before the decisions that settled
them, and the decision log is the authority where they disagree.

**Plain HTTP, not HTTPS.** The device has no clock and can never validate a
certificate, so the ed25519 signature is the whole of the protection and the
transport does not affect it. The consequence is a hosting constraint: the host
must not upgrade the request, because Zephyr's HTTP client does not follow a
redirect.

**Cold boot or the portal, not charger.** The specified trigger needs VBUS
detect on GPIO21, which is reserved and unwired, so the device cannot tell it
is plugged in.

**The same key signs firmware.** `trusted_key.h` here is the embedded ed25519
*public* key, generated by `tools/keygen.py`; the private half lives only in
the `BUNDLE_SIGNING_KEY` secret. It verifies question bundles and the OTA
manifest, which are the same statement about the same kind of artifact. It is
*not* the key that signs firmware images — that one is verified by MCUboot, not
by this application, and is described in
[docs/firmware_update.md](../../../docs/firmware_update.md).

Release firmware rejects unsigned (`"sig": null`) manifests, for a bundle and
for an image alike.
